# ApexCode — production-ready deployment package

Многостраничный сайт ApexCode с сохранением исходного интерфейса и подключаемой production-инфраструктурой: PostgreSQL, постоянные сессии, админ-панель, Telegram Admin Bot, приватные вложения, Stripe Checkout и автоматический HTTPS через Caddy.

## Что реализовано

1. **Админ-панель** (`/admin.html`): список пользователей и управление активностью аккаунтов, просмотр заказов и изменение статусов, просмотр обращений, ответы пользователям и скачивание приложенных файлов. Нельзя отключить самого себя или последнего активного администратора.
2. **Telegram Admin Bot**: уведомления о новых заказах/обращениях, список заявок и тикетов, изменение статусов заказов/обращений, ответы пользователям. Команды доступны только чату из `TELEGRAM_ADMIN_CHAT_ID`.
3. **PostgreSQL**: пользователи, тикеты, ответы, файлы, заказы, платежи и сессии хранятся в реляционной БД. Миграция `migrations/001_initial.sql` выполняется автоматически при старте. Нумерация заказов/обращений использует sequences.
4. **Вложения поддержки**: PDF, PNG, JPG, WEBP, TXT; до 8 МБ, один файл на обращение. Файлы не раздаются публичной статикой: доступ проверяется по владельцу тикета или администратору.
5. **Оплата**: Stripe Checkout. Сумма задаётся Price в Stripe, а не браузером; секретный ключ хранится только на сервере. Webhook проверяет подпись и переводит оплаченный заказ в работу.
6. **Публикация и HTTPS**: `Dockerfile`, `docker-compose.yml`, `Caddyfile`. Caddy получает и обновляет TLS-сертификаты автоматически при корректной DNS-записи и доступных портах 80/443.

## Быстрый запуск на своём компьютере

Нужны Node.js 20+ и доступный PostgreSQL 16+.

1. Скопируйте `.env.example` в `.env`.
2. Укажите `DATABASE_URL` для локального PostgreSQL, длинный `SESSION_SECRET` (не менее 32 символов) и `ADMIN_EMAIL`.
3. Установите зависимости: `npm install`.
4. Запустите: `npm start`.
5. Откройте `http://localhost:3000`, зарегистрируйте пользователя с адресом `ADMIN_EMAIL`, затем войдите и откройте `/admin.html`.

Схема базы данных и таблица сессий создаются автоматически. Для ручного применения схемы можно использовать `npm run db:migrate`.

## Публикация на VPS с автоматическим HTTPS

Нужен VPS с Docker Engine и Docker Compose, доменное имя и возможность изменить DNS.

1. Направьте A/AAAA-запись домена на публичный IP VPS. Убедитесь, что входящие порты TCP 80 и 443 доступны.
2. Скопируйте проект на VPS и создайте `.env` из `.env.example`.
3. Заполните как минимум:
   - `DOMAIN=example.com` — домен без `https://`;
   - `APP_URL=https://example.com`;
   - `POSTGRES_PASSWORD` — длинный уникальный пароль в URL-safe формате (буквы, цифры, дефис и подчёркивание);
   - `SESSION_SECRET` — случайная строка не короче 32 символов;
   - `ADMIN_EMAIL` — email администратора.
4. Запустите `docker compose up -d --build`.
5. Проверьте `https://example.com/api/health`. Должно вернуться `ok: true` и `database: connected`.
6. Зарегистрируйте аккаунт с `ADMIN_EMAIL` и проверьте `/admin.html`.

Docker Compose сохраняет данные PostgreSQL, загруженные файлы и сертификаты в именованных volumes. Не удаляйте volumes при обычном обновлении приложения. Резервная копия БД: `docker compose exec -T db pg_dump -U apexcode apexcode > apexcode-backup.sql`; каталог `uploads` также нужно регулярно архивировать.

## Telegram Admin Bot

1. Создайте бота через `@BotFather` и скопируйте токен в `TELEGRAM_BOT_TOKEN`.
2. Получите свой личный Telegram chat ID и внесите его в `TELEGRAM_ADMIN_CHAT_ID` (не используйте публичную группу).
3. Перезапустите контейнер: `docker compose up -d`.
4. Откройте чат с ботом и отправьте `/start`.

Команды:

- `/orders` — последние 10 заказов; кнопки меняют статус.
- `/tickets` — открытые обращения и их ID.
- `/status AC-O-00001 processing` — статус заказа (`pending`, `processing`, `completed`, `cancelled`).
- `/ticketstatus AC-T-00001 in_progress` — статус обращения (`open`, `in_progress`, `waiting`, `closed`).
- `/reply AC-T-00001 Текст ответа` — ответ пользователю.
- `/help` — справка.

Для бота используется long polling, поэтому отдельный публичный webhook Telegram не нужен. Если `TELEGRAM_ADMIN_CHAT_ID` не задан, команды не принимаются.

## Stripe Checkout

1. Создайте аккаунт Stripe и Product с одноразовым (one-time) Price в валюте/сумме, согласованной с вашими условиями.
2. Для начала используйте тестовый ключ `sk_test_...`; внесите его в `STRIPE_SECRET_KEY`, а идентификатор Price (`price_...`) — в `STRIPE_PRICE_ID`.
3. В Stripe Dashboard создайте webhook endpoint `https://example.com/api/payments/webhook` для события `checkout.session.completed`.
4. Скопируйте signing secret (`whsec_...`) в `STRIPE_WEBHOOK_SECRET`.
5. Перезапустите приложение и проверьте оплату тестовой картой из документации Stripe. Переключайте на live-ключи только после проверки продукта, цены, налогов, возвратов и юридических требований.

Кнопка «Оплатить согласованный заказ» на странице тарифов использует настроенный Stripe Price. Сумма не принимается от клиента. Если ключи не заполнены, API честно сообщает, что оплата не настроена.

## Переменные окружения

Полный шаблон находится в `.env.example`. В production обязательно замените `SESSION_SECRET`, `POSTGRES_PASSWORD`, задайте `DOMAIN`, `APP_URL`, `ADMIN_EMAIL` и `DATABASE_URL` (в Docker Compose он автоматически формируется из `POSTGRES_PASSWORD`). Никогда не коммитьте `.env` и не отправляйте токены в чат.

## Эксплуатация и безопасность

- Не храните данные банковских карт в ApexCode: платёжные данные обрабатывает Stripe Checkout.
- Файлы поддержки хранятся на сервере в закрытом каталоге и доступны только владельцу обращения/администратору.
- Для реального запуска настройте резервное копирование БД и каталога `uploads`, обновление зависимостей, мониторинг и политику хранения данных.
- Включите Stripe live mode только после самостоятельной проверки бизнес-настроек. Для реальных платежей могут требоваться регистрация бизнеса, проверка личности, налоги и условия возврата.
- HTTPS автоматически выпускается Caddy только при корректном DNS и доступности портов 80/443. ZIP не может сам купить домен, создать VPS или привязать платёжный аккаунт.
